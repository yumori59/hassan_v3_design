# サブエージェント委譲のオーケストレーション

## Overview

委譲の品質は「指示の質」だけでは閉じない。**報告は使う前に検証し、設計判断は手元に残し、
標準ゲート外の変更には検証手段を自作する** — この 3 つはオーケストレーター側の責務であり、
どれだけ良い指示を書いてもワーカー側では代替できない。

指示文の書き方 (7 要素テンプレート) は `.claude/rules/06-delegation-prompts.md` を参照。
本 skill はその前後の思考ステップを定める。

## 5 ステップ

```
① 分解 → ② 指示 → ③ 報告の検証 → ④ 統合 → ⑤ タスク固有検証
```

### ① 分解 — 委譲するのは「葉」だけ

委譲前に必ず自問する: **「受入基準と必要コンテキストを、いま全部文章化できるか?」**

- できる → 葉タスク。委譲してよい (調査・定型実装・一括変換)
- できない = 作業中に相互作用する判断が発生する (命名の衝突回避・既存仕様との整合・
  モード別の挙動差・ライブラリ制約への適応) → **コア。委譲せず自分でやる**

巨大タスクの丸ごと委譲は分解の放棄。葉に割ってから委譲し、葉同士が独立なら並列に出す
(`rules/03-parallel-development.md`)。

### ② 指示 — 7 要素テンプレート

`rules/06-delegation-prompts.md` に従う (目的 / 対象 / やること / 既存例 / 制約 / 完了条件 / 報告形式)。

### ③ 報告の検証 — 使う前に抜き取り照合

報告を成果物・次の委譲プロンプト・意思決定に取り込む**前に**:

1. 報告から **load-bearing な事実** (そのまま書き写す予定の文言・数値・色・パス・順序) を列挙する
2. その代表を一次ソースで照合する (grep / Read。数分で済む)
3. **1 つでも誤りが見つかったら、その報告の load-bearing 事実は全数照合に切り替える**

要約で壊れやすいもの: 正確な文言 (「評価サマリ」↔「評価サマリー」の類の表記ゆれ)、
丸められた数値・hex 値、並び順、実在しない file:line。
「報告が詳細」は「報告が正確」を意味しない。詳細な報告ほど転記が増え、誤りの混入面が広がる。

検証は実装完了後の照合だけでは遅い — 誤った事実を指示に埋めてワーカーを走らせると、
成果物ごと作り直しになる。

### ④ 統合 — 最終組み立てはオーケストレーター

複数ワーカーの出力の突き合わせ、境界 (公開 API・命名・既存仕様との接続点) の確認、
成果物への最終組み込みは自分で行う。ワーカーの「完了しました」は統合済みを意味しない
(`rules/04-review.md` と同じ原則)。

### ⑤ タスク固有検証 — 標準ゲートが効かないなら作る

その変更を標準ゲート (go build/vet/test、tsc/vitest/build) が**実行しない**なら、
「書けた」は無検証と同じ。使い捨てでよいので実行可能な検証を作り、
**実行コマンドと出力を証拠として完了報告に含める**:

| 変更の種類 | 検証手段の例 |
|---|---|
| 単体 HTML / モック | JS 抽出 → `node --check`。ヘッドレス Chrome で自動操作 (クリック・タブ切替) + DOM assert を仕込んだコピーを実行。スクリーンショットを撮って目視 |
| スクリプト / ワンオフツール | 代表入力で実行し、期待出力と diff |
| ドキュメント | 参照している file:line・コマンド・設定キーの実在を grep で確認 |

目視 (「ブラウザで開いて確認した」) は文言の 1 字違いを見落とす。機械照合 + 目視の順で。

## よくある間違い

| 間違い | 現実 |
|---|---|
| 報告が詳細なので信頼して転記 | 詳細さと正確さは無関係。③ の抜き取り照合を先に |
| ブラウザで見たので OK | 視認はレイアウト用。文言・値は grep で機械照合 |
| 標準ゲートが通ったので完了 | そのゲートは変更を実行したか? していなければ ⑤ |
| 検証は最後にまとめて | 誤った事実が指示に埋まると成果物ごと手戻り。使う前に照合 |
| 全部委譲した方が速い | コア判断を含むタスクの委譲は、差し戻しループで結局遅い |
| 急いでいるので照合を省く | 時間は並列化で稼ぐ (ワーカー実行中に自分は照合・ハーネス準備)。照合の省略は全書き直しで返ってくる |
| HEAD を見て照合した | 正は working tree。未コミット変更があるファイルは Explore の参照先とズレうる |

## 実例 (本リポジトリ: UI モックへの現行アプリ UI 再現)

成果物: `aidlc-docs/inception/conversational-ideation/ui-mockup.html` (git e7bfc81。修正なしでコミットされ、concept.md §UI から参照されている)。

① 調査は Explore に委譲、**モック実装と設計判断 (既存資料との命名衝突回避・一括表示モードの挙動・動的挿入 DOM のイベント委譲) は手元に残した** → ③ 報告の見出し文言・トークン実値を `IdeaDetailSections.tsx` / `tailwind.config.ts` への grep で照合し、報告に無い値 (gray-80 = #F7F7F7 等) を補完 → ⑤ 標準ゲート対象外の単体 HTML のため、`node --check` + ヘッドレス Chrome の自動操作テスト (14 項目 assert) + スクリーンショットで検証し、結果を完了報告に記載。
