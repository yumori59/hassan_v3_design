## 4. 受入基準 (AC-PV-1.1〜AC-PV-7.3)

> すべて **設計書の記述に対する受入基準**であり、実装コードに対するものではない。
> 「適切に」「必要に応じて」等の曖昧語を使わず、**記述の有無・一致・不在・件数**で判定できる形にしてある (DR-5)。
> 各 AC の検証方法は [plan-proto-v4.md](plan-proto-v4.md) §3 が定める。

### 4.1 評価軸の 3 軸構造

- **AC-PV-1.1** [ideas.md](../../../docs/design/API/ideas.md) §6.3 の**主軸が 3 軸に置き換わり**、
  各軸について ①**API のフィールド名 (snake_case)** ②**重み** ③**サブ基準 3 つとその配点** が表で書かれていること。
  サブ基準は **F-PV2 の 9 個と 1:1 対応**し、対応しない行・対応先の無いサブ基準が **0 件**であること。
  **プロトタイプの camelCase (`marketAppealScore` 等) をそのまま API 名にしない**理由が書かれていること (FE-2)
- **AC-PV-1.2** **重み (40/35/25) の SSOT が `entity/idea` の Go 定数**であることが明記され、
  **DB にも `settings` にも持たない**ことと、**却下案 (契約ごとに DB で持つ = 増分 2)** が書かれていること (PV-D1 / BE-2)
- **AC-PV-1.3** **アンカー 5 段 (score 10/8/6/4/2) の扱い**が軸ごとに書かれていること — **F-PV3**
  (市場魅力度だけが数値閾値、他 2 軸は定性) を踏まえ、**閾値表で機械計算する軸**と

- **AC-PV-1.4** **廃止・移動する軸の全件表**があり、旧主軸 5 つと旧補助軸 4 つの**計 9 軸すべて**について

  (C-16 / CV-DF5 の「どちらかを黙って落とさない」を継承)
